**Read spec.** project-spec.md (CDP v10.0, converted from CDP-manifesto-v10.0-desktop.pdf) and cdp-foundations.md (v3.0) are in place in the project folder. Both are the hardened, self-demolition-produced versions supplied by the author.

**Preliminary finding surfaced before Evaluate — plugin/spec version drift.**
The installed `cdp` plugin (plugin.json version 3.0.0) ships its own bundled reference copy of the protocol, and it does not match the v10.0/v3.0 documents this project is using:

- `document/cdp-manifesto.md` bundled in the plugin is headed "CDP v1.0 — Manifesto", with a flat 00–05 structure (Meta-Principle, Problem, Principle, Process in 5 linear steps, Personas, Severity, Exit Criteria) — no Phase 0/1/2 split, no facilitator role, no augmented-humans framing.
- The plugin also bundles `document/CDP-manifesto-v8.0` and `-v9.0` PDFs and `document/CDP-foundations-v1.0` / `-v2.0` PDFs — several versions behind the v10.0/v3.0 pair this project supplies.
- Memory file naming: plugin's `project.config.json` maps `project_memory` to `cdp-memory.md`; the v10.0 manifesto's own §05.4 documents the file as `project-memory.md`. Different name, and the schemas differ entirely (manifesto: frontmatter + Binding/Decisioni/Terminologia/Stato/Log sections in Italian; plugin's actual `cdp-memory.md`: no frontmatter, Defined Terms/Architectural Decisions/Open Promises/Session Log in English).
- Session file schema: the `session-start` skill's own `sessions/session-template.md` is a minimal 3-field template; a separate, richer `document/session-schema.md` (session_id/status open|complete|abandoned/type incl. "review"/vulnerability category taxonomy of 8 slugs/Exit Check block format) exists in the plugin but is not the one `cdp:session-start` actually fills in. The manifesto's own §05.4 session schema matches neither exactly (its `status` enum is only `open | closed`, and its `type` enum omits `review` entirely, even though `cdp:session-start` treats review as a first-class fourth type).
- The plugin's root `project-spec.md` is a marketing-oriented example (Brand Identity, Target Audience, Campaign Objective...) — confirming the protocol's origin in a marketing-specific plugin before the v10.0 manifesto generalized it, consistent with cdp-foundations.md §F0 (Origin) and §F9 (recurring pattern: "operational over philosophical").

Net effect: the plugin currently executing this session is running logic authored against an earlier, marketing-flavored, flatter version of the protocol than the one described in the v10.0 manifesto being tested. Behavior from `cdp:demolish` / `cdp:integrate` / `cdp:resume` should be expected to diverge from what §01–§05 of the v10.0 manifesto specifies, until the plugin is updated to match.
