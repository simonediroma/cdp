# 10 — Closing the Loop

## What "done" looks like

A live URL, and a written trace — from Lesson 09 — of at least four specific places where a different answer would have produced a different outcome. If you can't point to that trace, the loop technically ran but didn't prove anything: go back to whichever lesson feels thinnest (a demolition cycle that resolved too easily, a macro table you didn't actually check against your own spec) and press harder on it before calling this finished.

## The minicourse, looking back

You've now run the same underlying discipline — formalize, attack, decide, record — across five different moments: hardening a spec from nothing (Course 1), shipping it as a PoC (Course 2), extending a live product (Course 3), fixing what breaks in it (Course 4), and, in this course, running that entire front half yourself, end to end, on something you built rather than something you read about. None of these were five different methods. They're one method, run enough times, on enough different objects, that by now you should trust it does something a single unattacked draft never could: turn whatever's actually true about your project into a written record, checked harder than you'd have checked it alone.

If a term still trips you up anywhere in this sequence, the [Appendix](../appendix/00-index.md) — the full CDP Protocol deep dive, the glossary, and the external resource list — stays available as reference, not as a sixth course to work through start to finish.
